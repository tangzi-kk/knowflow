# KnowFlow 当前设计入口

这里只保留当前有效的设计决策和入口。已实施或被替代的设计稿已移入 `../history/`，不再作为当前开发任务。

## 当前产品决策

> S08 · AI 编程目录中的 PRD、技术设计和历史问题清单是背景依据；其中与当前 Vault 固定结构冲突的旧 v1 规则，以本页、`SPEC.md` 和 4.5 设计稿中的已确认规则为准。

- 飞书负责创作，Obsidian 负责整理与本地存储。
- KnowFlow 是唯一正式插件实现，由 Obsidian 插件、浏览器扩展和共享协议组成。
- 飞书采集、整理 proposal 和远端回写遵守各自确认边界；本地 Markdown 自动编码默认直接执行安全项。
- 4.3 的自动识别把新建/修改事件和全库扫描收口为自动事务；异常项单篇跳过，用户用右键选择标签并整理。
- 标签缺失时只根据文档自身内容给出封闭枚举建议，低置信度统一回退 `S` 并在预览中标明。
- 双方同时修改时暂停，不自动选择覆盖方。
- 浏览器和 Obsidian 的成功状态必须对应真实写入终态。
- UI 原型用于试验视觉和交互，不等于正式功能已实现。

## Obsidian 入口职责

- 文件右键菜单按用户意图分组：文件夹先提供“剪藏到这里”，然后是“修改标签”，最后才是可编码文件夹的“整理此容器编码”；不使用“检查并纠正”这类模糊动作名。
- 单篇、目录和多选分别显示“修改此文档标签”“修改此目录标签（含子目录）”“修改所选内容标签”，范围写在名称中，保护项不会伪装成可操作入口。
- 目录默认递归处理子目录中的 Markdown；目录名只定义范围，不作为第二套标签事实，也不自动改目录名。
- 标签选择严格来自协议枚举 `S/X/L/Z/Q/J`；`Q → Z` 只是示例，任何合法标签之间都使用同一事务路径。
- 文件名和界面默认显示短编码；完整编码折叠在详情中，YAML、同步事件、索引与唯一性逻辑仍使用完整编码。
- 左侧 KnowFlow 入口负责待确认任务、当前整理、同步状态和低频维护，不复制设置项。
- 设置页只管理长期配置，按“连接、同步与本地显示、飞书知识库、高级设置”组织。
- 编码是整理流程，不是独立设置；`lark-cli`、端口和旧版 Lark Doc 兼容信息只在高级区域出现。
- 全库自动识别是“发现 + 自动提交安全项”；设置控制本地自动编码是否启用。
- 文件夹自动编码把父文件夹当作容器，只处理容器内直接子文件夹；create/rename 事件按名称自然排序并从 `01` 连续编号，短编码显示在目录名，长编码保存在 `.feishu-sync/目录编码索引.json`，白名单及受保护路径永远跳过。
- Vault 目录结构是固定边界：根入口不编码，`🪧导引/` 与 `3️⃣附件文件/` 整树保护，`0️⃣输入/` 与 `1️⃣🗃知识池/` 二级入口固定、三级文件夹起编，`2️⃣输出/` 二级文件夹起编；自动、右键和索引共用同一策略。
- “剪藏到这里”只负责采集并生成 proposal；文件夹容器编码不写 YAML，Markdown 标签修改才进入文档事务；三者不共用事实源。
- 未接入真实运行链路的开关不得展示为可用功能。
