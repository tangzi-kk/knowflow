# KnowFlow 4.3 自动编码与右键菜单边界

## 决策结论

本地 Markdown 不再要求用户逐篇确认编码。插件在文档新建、修改或改名后，自动识别标签、分配唯一编码、更新 YAML 和文件名，并沿用现有恢复点、协调锁和回滚事务。文件名和界面默认只展示短编码（例如 `S01.a1`），协议层仍保存完整编码（例如 `26_0726_S_01_a1`）。

自动化只对“这一篇可以安全完成”的文档执行。保护目录、损坏 YAML、非法文档 ID、重复编码、目标路径占用和预览新鲜度失败会单篇跳过，并提示用户用右键手动修正；不会阻塞同一批次的其他文档。

飞书拉取、网页剪藏和远端回写仍保留 proposal/冲突确认边界，不因本地自动编码而静默覆盖远端内容。

## 触发逻辑

| 触发 | 行为 | 结果 |
| --- | --- | --- |
| 新建 Markdown | 800ms 防抖后加入本地自动整理批次 | 自动编码并改名 |
| 修改 Markdown | 与新建相同；插件自己刚写入的事件会被抑制 | 不重复编码 |
| 改名 Markdown | 重新读取 YAML 和正文，补齐或校正编码 | 自动保持唯一编码 |
| Ribbon/命令“自动识别并整理全库文档” | 递归扫描 Vault | 自动提交安全项 |
| 文件树右键 | 用户明确调整归类或处理异常 | 打开标签整理面板；自动编码仍不要求逐篇确认 |

## 自动执行边界

```text
文件事件 / 全库命令
        ↓
读取 YAML + 文档内容识别 + 全库唯一性检查
        ↓
安全项 → 恢复点 → 协调锁 → YAML 写入 → 临时换序 → 最终改名
        ↓
重建索引 → 审计 → 同步事件

异常项 → 跳过该篇 → Notice/活动记录 → 用户右键修改标签或调整编码
```

自动模式仍然检查：

- 受保护路径：`AGENTS.md`、`🪧导引/**`、隐藏目录；
- YAML 是否可解析，`文档ID`、状态和标签是否符合协议；
- 编码和目标路径是否唯一；
- 写入前内容哈希是否仍然匹配；
- 任一步事务失败时是否完整回滚。

## 右键菜单与标签整理面板

- 文件夹：`剪藏到这里…`（采集入口）；
- 单篇 Markdown：`修改此文档标签…`；
- 文件夹：`修改此目录标签（含子目录）…`；
- 多选：`修改所选内容标签（N）…`；
- 非 Markdown、保护路径会从多选中排除，并显示被忽略数量；
- 右键不做后台自动识别，只在用户明确选择标签后处理当前范围；
- 标签候选严格来自协议封闭枚举：`S（收集）`、`X（项目）`、`L（领域）`、`Z（资源）`、`Q（灵感）`、`J（技能）`；
- 目录默认递归处理子目录中的 Markdown，父目录和子目录只是范围，不把目录名伪装成 YAML 标签，也不自动重命名目录；
- 选择标签后先生成预览，再应用安全项；完整编码、YAML 字段和后端路径放在详情中；
- 标签变更只替换完整编码的标签段，保留日期、序号、层级和文档 ID；目标编码冲突的文档单篇跳过并提示；
- 完整编码、YAML 字段和后端路径放在“查看完整编码”折叠区，不干扰日常判断；Obsidian 的系统属性视图默认隐藏完整 `编码`，仍保留 `短编码` 作为日常入口；
- 文件名改为短编码前缀；完整编码仍写入 YAML `编码`、同步事件 `encoding`、索引和唯一性检查；
- 全库自动化不放进普通右键菜单，避免误触大范围扫描。

## 验收标准

- 新建一个无标签 Markdown 后，防抖结束自动出现合法标签、完整编码、短编码和短编码前缀文件名；不弹确认框。
- 自动改名/写 YAML 产生的 Obsidian 事件不会再次创建重复自动任务。
- 同批次存在坏文档或路径冲突时，安全文档仍完成，异常文档保持原样并提示右键修正。
- 右键标签整理单篇、多选和递归目录均能进入标签面板；混合选择不会因一个保护项导致整个菜单消失。
- 将目录内文档从任一合法标签切换到另一合法标签时，所有安全文档的 YAML、完整编码、短编码、文件名和索引保持一致，子目录中的文档同样处理。
- 纠错面板默认只显示短编码；展开详情可看到与短编码一一对应的完整编码，后端事件仍发送完整编码。
- 重载插件后，自动编码不依赖内存中的待确认任务；飞书 proposal 仍保持原有确认协议。
