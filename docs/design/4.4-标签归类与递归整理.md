# KnowFlow 4.4 标签归类与递归整理

## 决策

“剪藏”是内容进入 Obsidian 的来源动作；“标签归类”是进入本地后的整理动作。右键可以同时提供两个入口，但必须分开命名、分开事务：`剪藏到这里…` 负责采集，`修改标签…` 负责本地整理。截图中的 `S02 · 剪藏` 可以作为目录范围，但真正的标签事实仍来自其中 Markdown 的 YAML `标签` 字段。

右键菜单按用户要完成的事情命名：

- 文件夹先显示 `剪藏到这里…`；
- 单篇 Markdown：`修改此文档标签…`；
- 文件夹：`修改此目录标签（含子目录）…`；
- 多选：`修改所选内容标签（N）…`。

“纠错”不再作为正常入口名称；自动识别错误仍可通过同一标签修改面板修正。导引和附件保护区不显示这些写入口。

## 标签范围

标签候选由当前协议快照定义，不能自由发明：

| 标签 | 语义 |
| --- | --- |
| `S` | 收集 |
| `X` | 项目 |
| `L` | 领域 |
| `Z` | 资源 |
| `Q` | 灵感 |
| `J` | 技能 |

用户可以把当前标签改成任意另一个合法标签，例如 `Q → Z`、`S → J`，不是只支持某一组固定替换。

## 目录与子目录

目录只定义处理范围，不是第二套标签存储：

1. 选择目录时默认递归收集其中所有 Markdown，包括子目录。
2. 文件夹名称（例如 `S02 · 剪藏`）不自动重命名，避免把路径语义和文档标签混为一谈。
3. 每篇 Markdown 独立检查 YAML、文档 ID、编码和目标路径；安全项继续完成，冲突或损坏项单篇跳过。

## 事务变更

选择目标标签后，插件先生成预览，再通过现有知识整理事务提交：

- `标签` 改为目标枚举值；
- 完整编码优先只替换标签段，保留日期、序号、层级和文档 ID；如果目标标签下的同一序号已被占用，则自动分配空闲序号，仍保留日期、层级和文档 ID；
- 从完整编码重新派生 `短编码`，并更新短编码文件名前缀；
- 重建索引并发出完整 `encoding` / `shortEncoding` 同步事件；
- 重复事实、保护路径、损坏 YAML 和并发漂移不覆盖，保留恢复点并报告原因；目标标签序号占用不再阻断整批标签修改，而是安全分配新序号。

## 验收

- 单篇、目录递归、多选均能选择任意协议标签并生成可读预览。
- `Q → Z` 只是样例；所有 `S/X/L/Z/Q/J` 之间的合法切换均通过同一事务路径。
- 子目录 Markdown 与父目录范围内文档一致处理，目录名本身保持不变。
- 文档 ID、正文、日期和层级不被标签变更改写；冲突项不假装成功。
