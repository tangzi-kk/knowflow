# KnowFlow 4.5 文件夹自动编码与白名单

## 结论

文件夹是结构容器，不是 Markdown 文档。它不写 YAML，也不把目录名伪装成文档标签；只在文件夹名称显示短编码，并把结构长编码保存到 `.feishu-sync/目录编码索引.json`。

- 可见名称：`TAGnn · 文件夹名称`
- 长编码：`YY_MMDD_TAG_NN`，只供索引、唯一性检查和后端逻辑使用
- 协议标签：`S / X / L / Z / Q / J`
- 序号：按标签在整个 Vault 内使用 `01–99`，不是每个父目录重新计数

例如新建“剪藏”目录，会按名称信号优先归类为 `Z01 · 剪藏`，索引记录类似 `26_0802_Z_01`。低置信度名称回退 `S`，插件会在 Notice 中提示。

## 自动触发

开启设置“自动识别并编码文档”后，Vault 的文件夹 `create` 和 `rename` 事件进入同一条防抖、串行事务链：

1. 检查保护目录和白名单。
2. 根据文件夹名称的确定性信号选择标签；没有信号时回退 `S`。
3. 预览目标名称、序号和长编码，检查目标路径与序号冲突。
4. 先改名，再写目录编码索引；索引写入失败会尝试恢复原名称和旧索引。
5. 成功后提示“文件夹已自动编码”；自身 rename 事件在短窗口内抑制，避免循环。

插件不会在启动时批量重命名已有文件夹，也不会因为父目录编码而静默改写整棵旧目录树。需要补齐旧目录时，使用右键逐个处理，或先在测试 Vault 预览。

## 白名单与保护边界

设置页的“文件夹编码白名单”使用相对 Vault 根目录的路径，支持逗号或换行分隔。白名单命中目录及其子目录都会跳过自动编码和手动文件夹编码。

以下路径始终保护，不能通过设置解除：

- Vault 根目录；
- Vault 根目录下的一级入口目录（例如 `0️⃣输入`、`1️⃣🗃知识池`、`2️⃣输出`、`3️⃣附件文件`）；
- `.obsidian/`、`.feishu-sync/` 和其他以 `.` 开头的隐藏目录；
- `🪧导引/` 及其全部子目录；
- `3️⃣附件文件/` 及其全部子目录；
- 名为 `AGENTS.md` 的保护路径。

固定结构的编码起始层级：

- `0️⃣输入/` 与 `1️⃣🗃知识池/` 的二级语义入口只负责分流，不自动改名；从三级文件夹开始编码。
- `2️⃣输出/` 的二级文件夹可以编码，继续向下的文件夹沿用同一规则。
- 右键入口与自动事件都执行同一层级判断；导引、附件和固定入口不会显示文件夹编码面板。

白名单只影响文件夹结构编码，不影响 Markdown 文档的自动编码、飞书采集或远端回写。

## 右键菜单设计（按用户意图分组）

文件树右键只呈现当前对象能完成的动作，并按“进入内容 → 整理内容 → 调整结构”的顺序排列：

- 文件夹：`KnowFlow：剪藏到这里…`，把飞书链接或 token 采集到当前文件夹；这是采集动作，不修改标签或目录编码。
- Markdown：`KnowFlow：修改此文档标签…`，只处理当前文档。
- 文件夹：`KnowFlow：修改此目录标签（含子目录）…`，递归处理目录内 Markdown；目录名称本身不改名。
- 多选：`KnowFlow：修改所选内容标签…`，按当前选择处理，保护项自动忽略并显示数量。
- 可编码文件夹：`KnowFlow：调整此文件夹结构编码…`，只修改目录短编码和本地结构索引；固定入口、导引、附件和白名单目录不显示该项。

采集和整理不共用一个写入事务：剪藏先落地并生成 proposal，标签修改复用 Markdown 预览/备份/原子提交事务，结构编码复用目录索引事务。菜单不使用“检查并纠正”“自动编码此目录”等会让用户误以为会执行未知范围的名称。

### 标签修改面板

标签修改面板只保留三块内容：

1. 一个标签下拉框，选择 `S/X/L/Z/Q/J` 及其语义名称；
2. 修改后的文件名/路径预览，逐项显示“原名称 → 新名称”；
3. “取消”和“应用修改”按钮。

普通界面不展示完整编码、重复编码、事务编号、内部索引或原始阻断消息。没有可修改项时只显示“当前没有可修改的文档”，详细原因保留在后台活动记录和调试日志中。

在文件树对可编码文件夹右键选择“KnowFlow：调整此文件夹结构编码…”。面板会显示：

- 当前路径与即将显示的短编码；
- 协议标签的语义名称；
- 可折叠查看的目录长编码；
- 白名单、保护路径、目标占用或序号冲突等阻断原因。

标签改变只会修改文件夹结构编码。对目录内 Markdown 的标签统一调整，使用相邻的“KnowFlow：修改此目录标签（含子目录）…”；它们是两个不同范围、不同事实源的动作。

如果目标标签下的同一序号已经被其他目录占用，面板会阻断操作，不自动覆盖或制造重复长编码；用户可换标签或先处理冲突。

## 验收要点

- 新建“项目”“剪藏”等目录能自动得到可读短编码和提示。
- `Q → Z` 等任意合法标签变更可预览；遇到 `Z01` 占用时失败关闭。
- 白名单目录及子目录名称保持原样。
- `.feishu-sync/目录编码索引.json` 损坏时阻断写入，不静默清空。
- 文件夹编码不写入文档 YAML，不改变飞书 proposal / pushback 的确认边界。
