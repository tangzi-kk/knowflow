# KnowFlow 4.2 二次设计：自动识别与全库整理

> 历史设计基线：4.3 已将本地安全项改为自动提交；当前行为以 [`4.3-自动编码与右键纠错.md`](4.3-自动编码与右键纠错.md) 为准。

## 决策结论

用户不应为每篇文档单独点击“编码”。KnowFlow 4.2 把日常整理拆成四个职责：

1. **发现**：监听新建、修改和改名事件，并提供一次性的全库扫描。
2. **识别**：先沿用合法 YAML 标签；缺失或非法时，只用标题、正文和关键词生成可解释的封闭枚举建议。
3. **决策**：把本批次所有 YAML、文件名、编码和阻断原因放在一个预览中，由人一次确认。
4. **执行**：插件在协调锁内分配唯一编码，写入文档 ID、短编码和文件名，创建恢复点，失败自动回滚。

自动识别不是静默改名，也不把 Agent 或运行时索引变成第二套事实源。

## 从第一性原理重排入口

| 用户问题 | 唯一入口 | 结果 |
| --- | --- | --- |
| 我刚写了一篇文档 | 自动发现待整理文档 | 进入待确认任务，不直接改文件 |
| 我的库里有很多旧文档 | Ribbon/命令：自动识别全库文档 | 一个递归批量预览 |
| 我只想整理当前内容 | 文件树右键：整理此文档/目录/所选内容 | 直属范围预览 |
| 我需要知道是否安全 | 预览中的阻断、冲突、警告和变更列表 | 有问题就不允许确认 |
| 执行后发现不对 | 事务恢复点与显式回滚 | 不覆盖回滚后的新编辑 |
| 飞书拉取新文档 | fetch/clip proposal | 落地后进入同一待确认队列 |

设置页只保留长期配置。`自动发现待整理文档` 是唯一自动化开关；它只控制发现，不授予绕过确认的写权限。

## 识别规则

- 合法 `标签`（`S/X/L/Z/Q/J`）优先级最高，置信度为高。
- 否则按标题、关键词、正文前 12,000 个字符的确定性规则评分；标题权重最高，正文权重最低。
- 规则只产生已注册标签，不读取目录名，不凭目录推断分类。
- 没有足够信号时回退 `S（收集）`，标注“低置信度回退”，由用户在预览中决定。
- 文档 ID、日期和已有合法编码不会因重新扫描而随机变化；已有合法编码只在标签明确变化时同步标签段。

## 批量事务边界

```text
事件/全库命令
      ↓
读取 YAML + 识别建议 + 全库唯一性检查
      ↓
批量预览（待写字段、目标文件名、阻断、冲突、低置信度）
      ↓ 人工一次确认
恢复点 → 协调锁 → YAML 写入 → 临时路径换序 → 最终改名
      ↓
重建派生索引 → 审计 → 同步事件
      └─ 任一步失败：逆序恢复，禁止假成功
```

扫描排除 `AGENTS.md`、`🪧导引/**` 和任何隐藏目录；损坏 YAML、非法文档 ID、非法状态、重复编码和路径占用会停在预览中。frontmatter 仍是唯一事实源，`.feishu-sync/` 只保存恢复点、索引和审计。

## 验收标准

- 新建/修改 Markdown 在短暂防抖后生成待确认任务；不调用 `commitPlan`，不静默改名。
- 全库命令递归扫描，一次预览可包含多篇文档；已合规文档只计入跳过，不重复改名。
- 缺失标签能得到 `X/L/Z/Q/J` 的可解释建议或 `S` 低置信度回退；不猜测目录标签。
- 预览确认后沿用现有恢复点、冲突复核、事务回滚和同步事件；自动模式只提交安全项，重复编码、损坏 YAML 等阻断项原样留在待处理列表；任何漂移都失败关闭。
- 保护路径永远不进入写入计划；GitHub 发布包不包含 Vault 正文、附件、Token 或本地状态。

## 非目标

- 本版本不引入 AI API，不把自然语言模型输出当作事实。
- 本版本不改变协议主版本、不增加新的 YAML 枚举、不默认自动回写飞书。
- 本版本不删除旧文档；清除编码、远程删除和同步冲突继续使用各自的显式预览流程。
